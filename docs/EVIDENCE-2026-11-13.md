# BitOS Pay reference core — evidence 2026-11-13

Status: **Local synthetic evidence only.** This record does not claim production,
pilot, CI or real-money readiness. No independent security or reconciliation
review exists. A 2026-11-14 addendum records env-gated sandbox onboarding and
migration `0006`. See [EVIDENCE-2026-11-14](EVIDENCE-2026-11-14.md) for the later
Blink/Strike adapter evidence.

## 1. Scope implemented

The reference core in [`../service`](../service) implements the core Pay slice:

- Payment intent, attempt and invoice state with terminal-state protection.
- SAT-only integer amounts and explicit scale validation.
- Idempotent intent creation with request digest and conflict detection.
- Sandbox Lightning adapter boundary (`MockLightningProvider`).
- Provider-proof settlement, duplicate-event handling and late-settlement
  quarantine.
- Double-entry ledger with fee snapshot, immutable posted entries and a balance
  projection labeled `ledger_derived`.
- Merchant-scoped API keys (hashed, prefix searchable, scopes, sandbox/live flag)
  with create/list/revoke endpoints.
- Env-gated, per-IP-limited sandbox onboarding that creates an organization,
  sandbox merchant, provider connection and one-time `bp_test_` key; the
  organization records `created_via=sandbox_onboarding` and no ID subject.
- Signed webhook outbox and delivery with HMAC, retry backoff, delivery log,
  replay and endpoint disable.
- Direct invoice creation and read.
- Cursor/status pagination for payments and transactions.
- Sandbox SAT/LAK quote snapshots with a 60-second expiry.
- Ledger-derived settlement summaries and stored reconciliation records.
- Partial and full sandbox refunds with a `payments:refund` scope, amount
  ceiling, idempotency, proportional fee reversal, separate `refunds` records
  and a `refund.succeeded` webhook.
- Per-merchant amount, rolling daily-volume and per-minute velocity limits plus
  the merchant-status gate, checked before provider invoice creation.
- OpenAPI 3.1 description at `/openapi.json`.
- Server-side `@bitos/pay-js` client with typed resources, generated
  idempotency keys, error mapping and raw-body webhook signature verification.
- Reference console session: sandbox-key login, hashed HttpOnly session cookie,
  CSRF-protected writes, key revalidation and logout.
- Live `/console/` page with payment monitoring, balances, settlement, payment
  creation, scoped API-key create/revoke, webhook registration/disable/replay and
NIP-07 Nostr link/login, opt-in local nsec and relay-gated NIP-46 adapters.
- Fastify API with schema validation, request-scoped errors and request ids.
- Layered layout: pure domain, application use cases/ports, infrastructure
  adapters/repositories and API route modules.
- Static synthetic dashboard and checkout UI plus a live console, with shared
  design tokens, English/Lao copy, theme switch, keyboard-accessible drawer and
  receipt state.

Not implemented: real provider or provider refund, production
dashboard/checkout/developer console, Nuxt/React/node SDK wrappers, fiat payment,
payouts, BNOS adapter, live callback signature verification, admin APIs for
changing risk limits, login rate limiting, MFA, staff roles, open registration,
atomic key rotation and a durable queue.

## 5. Known limits

- The live test used PostgreSQL 16.14 in a disposable development container. Other
  majors, production extensions, TLS, backups and restore are not tested.
- The sandbox provider is in-memory; restarting the process loses its invoice
  verification state.
- Webhook delivery is an in-process worker, not a durable queue.
- No CI is configured or claimed.
- No independent security review, legal review, provider reconciliation drill or
  pilot authorization exists.
- The demo dashboard/checkout is static and does not call the API. The live
